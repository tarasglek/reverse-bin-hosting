# Reverse Bin v0.0.11

## Highlights

- Apps get a single public-address variable, `REVERSE_BIN_PUBLIC_HOST`, and are always served as `https://$REVERSE_BIN_PUBLIC_HOST`.
- `utils/run-reverse-bin-app.sh` serves `https://<app>.localhost:9443` with Caddy's local CA, so local runs follow the same HTTPS contract as production.

## Breaking changes

- `REVERSE_BIN_PUBLIC_URL` (added in v0.0.10) is no longer injected; use `https://$REVERSE_BIN_PUBLIC_HOST`.
- The packaged Caddyfiles pass `--public-host` and require the bundled reverse-bin-detector v0.1.17. If you kept a locally modified v0.0.10 Caddyfile, replace `--public-url={reverse_bin_public_url}` with `--public-host={reverse_bin_public_host}` and drop `https://` from the map's third column.
- `utils/run-reverse-bin-app.sh` takes an HTTPS `PORT` (default 9443) instead of an HTTP port.

## Full list of changes

- Bundle reverse-bin-detector v0.1.17, which replaces `--public-url` with `--public-host`.
- The packaged Caddyfiles map each host to its app directory and bare public host; apex and `www.` still map to one host so they share one backend.
- The local runner uses `tls internal` with `skip_install_trust`, so Caddy never installs its CA into the system trust store, and prints the CA path for `curl --cacert`.
- README and the bundled reverse-bin-web-apps skill document the `https://$REVERSE_BIN_PUBLIC_HOST` contract and `${REVERSE_BIN_PUBLIC_HOST%%:*}` for bare-hostname settings.
