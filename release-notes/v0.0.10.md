# Reverse Bin v0.0.10

## Highlights

- Every app now receives `REVERSE_BIN_PUBLIC_URL` (for example `https://post.example.com`) and `REVERSE_BIN_PUBLIC_HOST`, so apps can configure CSRF origins, allowed hosts, OAuth redirects, and absolute links without hard-coding their domain.

## Breaking changes

None for packaged installs. The packaged Caddyfiles pass `--public-url` to reverse-bin-detector, which requires the bundled detector v0.1.16 or newer; do not pair them with an older hand-installed detector. Running app backends restart once after the upgrade because their detector arguments changed.

## Full list of changes

- Bundle reverse-bin-detector v0.1.16, which accepts `--public-url` and injects the public URL and host into the app environment unless the app sets them itself.
- The packaged Caddyfiles map each host to its app directory and canonical `https://` URL. The apex domain and `www.` both map to the `www` app with the apex URL, so they keep sharing one backend.
- `utils/run-reverse-bin-app.sh` passes its local `http://127.0.0.1:PORT` URL so local runs see a correct public URL.
- The logs dashboard derives its GoAccess WebSocket URL from `REVERSE_BIN_PUBLIC_HOST`; `setup.sh` no longer reads `DOMAIN_SUFFIX` or writes `LOGS_WS_URL`. Existing logs app installs are left unchanged.
- README and the bundled reverse-bin-web-apps skill tell apps to use the public URL variables instead of hard-coding domains.
- Packaging checks assert the canonical apex/www mapping, and the logs app check accepts the currently pinned GoAccess version.
